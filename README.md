# ComplianceRadar 出海合规雷达

> **Sellers enter "what I sell + where I sell it" → get which regulations apply, what changed recently, and what to do next — every conclusion backed by a link to its official source.**

面向出海卖家的法规合规自查工具。输入「商品类目 + 目标市场」，输出**适用法规清单 · 法规变化时间线 · 可执行待办清单**，**每条结论强制附官方原文链接**。

## 这个项目解决什么问题

### 场景

一个卖家要把商品卖到海外市场，必须先搞清楚：**我这个品类，目标市场有哪些法规要求？最近有没有变化？我现在要做什么准备？**

### 现状有多难

| 痛点 | 具体表现 |
|---|---|
| **法规分散** | 各国官网各查一遍，欧盟要查 EUR-Lex，美国要分别查 FDA / FCC / CPSC |
| **语言与专业门槛** | 全是英文法律术语，非专业背景根本读不懂 |
| **更新跟不动** | 法规频繁修订甚至整部被取代，卖家往往事后才知道 |
| **通用 AI 不可靠** | 直接问大模型容易编造条款号、引用已被废止的旧法规，且不给来源 |

### 两个真实案例

**案例一：法规已被取代，AI 还在答旧法**

欧盟儿童玩具法规已经更替：

- **Regulation (EU) 2025/2509** 于 2025-11-26 通过，**2026-01-01 生效**
- 将于 **2030-08-01 起全面取代** 沿用十余年的 **Directive 2009/48/EC**

一个做了十几年玩具出口的卖家，如果现在还按旧指令准备合规，就选错了标准。而直接问通用大模型，它多半还会回答已经过时的 `Directive 2009/48/EC`，且不提供来源链接。

**案例二：AI 会编造不存在的法规编号**

我们在实测中向通用大模型询问法规信息时，曾得到一个编号 `32015R1000`。经欧盟官方接口（EUR-Lex SPARQL）逐一核查，**这个编号在官方数据库中根本不存在**。

这类错误对卖家是致命的 —— 照着一个不存在的编号去准备合规，等于白做。而**大模型不会告诉你它在编**，它会用同样肯定的语气说出来。

**这正是本工具的切入点：不靠 AI「记得」法规，而是让它「查」到法规 —— 且每条结论都能点开官方原文核实。**

## 为什么是这些品类与市场

### 品类不是随手选的 —— 是监管数据标出来的

数据来源：欧盟委员会《2024 Safety Gate 年度报告》（2025-04 官方发布）。2024 年全欧危险产品警示 **4137 次**，创 2003 年系统建站以来最高纪录。被警示最多的品类：

| 警示品类 | 占比 | 本项目是否覆盖 |
|---|---|---|
| 化妆品 | **36%** | ✅ 美妆个护 |
| 玩具 | **15%** | ✅ 儿童玩具 |
| 电器 | **10%** | ✅ 电子电器 |
| 机动车 | 9% | — |
| 化学品 | 6% | — |

**召回榜前三名，正是本项目覆盖的三个品类。** 这不是我们先定品类再找依据，而是监管机构的真实召回数据告诉我们：这些品类最容易出事、最需要有人帮卖家看清规则。

### 目标用户同样是官方数据里被点名的

同一份报告：

| 数据 | 数值 |
|---|---|
| 警示产品最大来源地 | **中国，占 40%** |
| 扣除化妆品后 | **中国占 61%**（第二名欧洲经济区仅 19%） |
| 2024 年欧盟进口低价商品 | 46 亿件，日均 1200 万个包裹，**其中 91% 来自中国** |

> 欧盟每 10 件被查出的危险产品，有 4 件（扣掉化妆品是 6 件）来自中国。**中国卖家正是最需要提前搞清法规的人群 —— 我们的目标用户，是被官方数据点名的。**

### 市场选择有出口数据支撑

数据来源：中国海关总署（2025 年数据）、安永《2025 消费品出海白皮书》。

| 出口目的地 | 占比 |
|---|---|
| **美国** | **34.2%（第一）** |
| 英国 | 8.1% |
| 德国 | 6.2% |
| 法国 | 4.5% |

出口品类结构（海关总署 2025）：服饰鞋包及珠宝配饰 **21.8%（第一大）**、手机电脑等数码产品及配件 **16.5%**、家用办公电器及配件 **14.3%** —— 恰好对应本项目的纺织服装与电子电器。

> **结论**：本项目先做欧盟与美国两个市场，不是保守，而是对准了「出问题最多 × 中国卖家最多」的交集。这两个市场也是两套**完全不同的官方数据源**（欧盟 EUR-Lex、美国 eCFR）—— 两条链路都跑通，证明方法论可复制，换市场只需新增一个数据源适配器（详见[路线图](#路线图)）。

## 核心特点

| 特点 | 说明 |
|---|---|
| **可核验** | 每条结论强制回挂官方原文链接，拿不到链接的内容一律不输出 |
| **有时效** | 追踪法规变化，标注「已被取代」「新近修订」「过渡期安排」 |
| **可执行** | 把法律语言翻译成卖家能执行的动作（如「需加贴 CE 标识」） |
| **有边界** | 明确声明适用范围，范围外输入直接拒绝，不做硬编答案 |

## 功能模块

| 模块 | 名称 | 输入 | 输出 |
|---|---|---|---|
| **M1** | 合规地图 | 商品类目 + 目标市场 | 适用法规清单：中文名 / 官方英文标题 / 官方编号 / CELEX 号 / ELI 链接 / OJ 出处 / 生效日期 / 是否仍有效 |
| **M2** | 变化时间线 | 商品类目 + 目标市场 | 近期变化条目：变化摘要 / 影响说明 / 生效或发布日期 / 官方链接 |
| **M3** | 待办清单 | 商品类目 + 目标市场 | 可执行动作 + 来源条款链接，支持导出 |
| **M4** | 对照演示 | 同一问题 | 双栏对比：通用大模型直答 vs 本工具 |

## 技术架构

```
官方数据源（EUR-Lex · FDA · FCC · CPSC）
        │  确定性程序：抓取、解析、去重、URL 有效性校验、按类目建索引
        ▼
   法规语料库（含元数据：发布日期、生效日期、适用日期、官方链接）
        │  结构化检索：按「类目 + 市场」标签精确筛选（小规模强结构化语料，无需向量检索）
        ▼
   LLM 生成层
        · 条款筛选归类  → M1 清单
        · 变化对比与摘要 → M2 时间线
        · 法规语言 → 待办动作 → M3 清单
        │  确定性程序：引用对齐（每条输出必须回挂官方链接，无链接不输出）
        ▼
   Web 界面（部署于 ModelScope 创空间）+ 对照演示模块（M4）
```

### AI 与确定性代码的分工

| 环节 | 由谁完成 | 原因 |
|---|---|---|
| 理解、归类、摘要、翻译 | **LLM** | 这是语言任务，LLM 擅长 |
| 抓取、URL 校验、引用对齐、缓存去重 | **确定性代码** | 这些要求准确性，不能交给概率模型 |

> **设计原则**：LLM 只做「理解」类工作，凡是要「准确」的环节全部交给确定性代码。这是本产品可信度的技术基础。

### 一次查询的完整链路

```
① 用户输入        品类（如「儿童玩具」）+ 市场（如「欧盟」）
        ▼
② 结构化查表      确定性代码按「类目」「机构」两列筛选语料库
  （确定性）        · 纯本机操作，不联网、零 API 成本、毫秒级返回
        ▼
③ 结果集送 LLM    把命中的法规原文数据交给大模型组织成中文
  （LLM）           · 硬约束：只能使用给定内容，不得补充自行「知道」的法规
        ▼
④ 引用对齐        确定性程序逐条校验输出是否回挂官方链接
  （确定性）        · 无链接的条目一律不输出 —— 这是不可砍的底线
        ▼
⑤ 输出            法规清单（M1）/ 变化时间线（M2）/ 待办清单（M3）
```

**为什么不用向量检索（RAG）？**

| 对比 | 本期语料的实际情况 |
|---|---|
| 语料规模 | 仅 88 条，**小规模** |
| 数据结构 | 每条都有严格的结构化标签（类目、机构、编号），**强结构化** |
| 结论 | 按标签**精确筛选**，比向量检索更准、更快、零成本，且结果 100% 可解释（能追到具体是哪一行数据） |

> 向量检索适用于大规模非结构化语料；本项目是「小规模 + 强结构化」，用精确筛选才是对的技术选择。

**这套设计的额外好处**：即使大模型调用失败或配额耗尽，程序依然能输出原始法规清单（只是没有中文润色）—— **演示不会因 API 问题而中断**。

## 快速开始

> ⚠️ 代码实现正在进行中（截至 2026-10-14）。以下为规划中的使用方式。

### 环境要求

- Python 3.10+
- 可访问官方数据源

### 安装

```bash
git clone https://github.com/cristiano138/Chinese-Enterprises-Going-Global-Radar.git
cd Chinese-Enterprises-Going-Global-Radar
pip install -r requirements.txt
```

### 配置

复制环境变量模板，填入你的 API Token：

```bash
cp .env.example .env
# 编辑 .env，填入 MODEL_API_TOKEN
```

> 🔒 **安全提示**：API Token 必须通过环境变量传入，不要写死在代码里。本项目已在 `.gitignore` 中排除 `.env`。

### 运行

```bash
python app.py
```

浏览器打开提示的本地地址即可使用。

## 数据来源与引用规范

### 本期覆盖范围

| 项 | 范围 |
|---|---|
| 市场 | 欧盟（EU）+ 美国（US） |
| 品类 | 儿童玩具、电子电器、纺织服装、美妆个护、食品接触材料 |
| 横切维度 | 标签标识、通用（如欧盟 GPSR 通用产品安全条例，对所有消费品适用） |
| 合规维度 | 产品安全法规、标签标识 |
| 语料规模 | **88 条**（欧盟 29 + 美国 59），每条含官方标题、官方编号、官方链接、生效日期 |

> **关于「标签标识」与「通用」**：它们不是并列品类，而是**横切维度** —— 任何品类都要遵守标签要求，任何消费品都可能被通用法规覆盖。这恰恰是设计优点：**两个维度覆盖所有品类。**

### 语料现状

| 品类 | 欧盟 | 美国 | 合计 |
|---|---|---|---|
| 儿童玩具 | 3 | 15 | 18 |
| 电子电器 | 9 | 10 | 19 |
| 纺织服装 | 4 | 11 | 15 |
| 美妆个护 | 1 | 6 | 7 |
| 食品接触材料 | 7 | 13 | 20 |
| 标签标识 | 4 | 4 | 8 |
| 通用 | 1 | 0 | 1 |
| **合计** | **29** | **59** | **88** |

全部数据来自官方一手接口（欧盟 EUR-Lex SPARQL、美国 eCFR API），每条链接均已程序验证。完整底表见 [`data/语料核对表_完整版.csv`](data/)。

### 什么算「官方来源」

三个条件缺一不可：

| 要素 | 判定标准 |
|---|---|
| **域名** | 必须是 `eur-lex.europa.eu`（欧盟）或对应国家监管机构官方域名；ELI 永久标识可为 `data.europa.eu/eli/...` |
| **法源** | 落在《欧盟官方公报》（Official Journal, OJ）等官方公报上公布的文本 |
| **标识** | 能找到 **CELEX 号**与 **ELI 标识**，且编号能对回官方公报 |

### 明确不算官方来源

- 第三方法律数据库、律所或媒体解读、百科条目
- AI 生成的摘要
- 官方站的「解读性摘要」页（属官方摘要，非法条原文）
- 无 CELEX / ELI 标识、或点进去回不到原文的链接

> 📖 详细规则见 [`docs/04-官方来源判定指南.md`](docs/04-官方来源判定指南.md)

### 关于「链接打不开」的判定规则

官方站点（欧盟 EUR-Lex、美国 FDA / FTC / CPSC / FCC 等）普遍部署了人机验证墙或访问限制，**程序化访问常被拦截**（返回 202 挑战页、403，或指向误导页），但**真人在浏览器中可正常打开**。

| 情况 | 判定 |
|---|---|
| 程序访问被拦（202 / 403 / 异常跳转） | **不等于链接失效** —— 记「需人工浏览器验证」 |
| 真人浏览器也打不开 | 才是真的链接有问题 |

**规则：真人浏览器能打开的一律记为「可打开」，不因程序报错就判定链接失效、更不要因此去改链接。**

## 路线图

### 本期实现

- 2 个市场（欧盟 + 美国）× 5 个品类
- 2 个合规维度（产品安全法规 + 标签标识）
- 4 个功能模块（M1–M4）

### 后续规划

| 方向 | 内容 |
|---|---|
| **多市场** | 日本、韩国、英国（UKCA）、加拿大、澳大利亚、沙特、巴西 —— **每个新市场 = 新增一个官方数据源适配器**（本期已用欧盟 EUR-Lex、美国 eCFR 两套完全不同的数据源验证该模式可行） |
| **多维度** | 税务合规（VAT）、知识产权、海关清关、数据合规 |
| **全流程** | 检出问题后就近对接检测机构 / 律师 / 货代 |
| **行业专版** | 玩具版、电子版、纺织版、美妆版、食品接触材料版 |
| **订阅服务** | 法规变化主动推送 |

**架构上的可扩展性**：

| 扩张方向 | 架构支撑 |
|---|---|
| 加市场 | 数据源做成适配器模式，新增市场 = 新增适配器 |
| 加品类 | 语料库按类目标签索引，新增品类 = 新增标签 |
| 加维度 | 模块按查询维度解耦，新增维度 = 新增模块 |
| 加能力 | 前端按结果卡片组合，新增能力 = 新增卡片 |
