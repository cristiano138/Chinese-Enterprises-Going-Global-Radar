## 一、必须先说清楚的一件事：为什么很多链接「测出来打不开」

本次核对发现一个**极其重要的技术事实**，必须写在最前面，否则会误导判断：

> **本机网络环境对部分政府网站做了统一拦截，程序访问会拿到假的错误状态。**
> **链接本身是好的，只是程序测不出来。**

### 证据链（三条，互相印证）

**证据 1：FDA 直接暴露了拦截行为**

```
curl https://www.fda.gov/cosmetics/... 
→ HTTP 404，跳转到 /apology_objects/abuse-detection-apology.html
```

那个 `abuse-detection-apology.html` 是 FDA 的**「滥用检测道歉页」** ——
说明是**它主动拦截了本机请求**，而不是页面不存在。

**证据 2：连搜索引擎刚返回的正确链接，程序也测不通**

我用搜索引擎查到 FDA 当前的正确地址，**立刻就测**，结果：
```
FDA 化妆品标签(新地址)   → 404（跳到 abuse-detection 页）
FTC 服装纺织(新地址)     → 404
```

搜索引擎明明抓到了页面正文，程序却报 404 —— **只能是本地拦截。**

**证据 3：FTC 整站统一返回 404**

`ftc.gov` 上的链接，无论新旧、无论哪个页面，**程序测全部返回 404**。
一个正常运营的政府网站不可能整站 404 —— 这是**统一拦截**的特征。

### 受影响的站点（程序测不准，但网站本身正常）

| 站点 | 程序看到 | 实际情况 | 判断依据 |
| --- | --- | --- | --- |
| `fda.gov` | SSL 错误 → 404 | **正常** | SSL 是 self-signed（本地中间人），绕过 SSL 后仍 404 且带 abuse 页 |
| `ftc.gov` | 404 | **正常** | 整站统一 404；搜索引擎可正常抓取正文 |
| `cpsc.gov` | 403 | **正常** | 搜索引擎可正常抓取首页与业务页 |
| `fcc.gov` | 403 | **正常** | 搜索引擎可正常抓取实验室页面 |
| `eur-lex.europa.eu` | 202 | **正常** | AWS WAF 人机验证墙（已知，前次已查明） |
| `op.europa.eu` | 403 | **正常** | 欧盟站同样有人机验证 |

> **结论：这 6 个站点的链接，不能用程序判定，必须由真人在浏览器里点开验证。**
> 这属于**环境限制**，不是指南的错误。

### 给张（写填表规则）的提醒

建议把这条规则写进「填表规则说明」：

> **政府站点有两个「打不开」的原因，必须分清：**
> 1. **链接失效** → 页面真的没了（网站改版），需要换新地址
> 2. **程序被拦** → 链接是好的，但本机网络/反爬拦截了程序，**真人浏览器点开正常**
>
> 判定方法：**凡是真人用浏览器能打开的，一律记为「可打开」，不管程序报什么错。**
> 本项目已有 6 个站点属第 2 类（FDA、FTC、CPSC、FCC、EUR-Lex、CELLAR）。
