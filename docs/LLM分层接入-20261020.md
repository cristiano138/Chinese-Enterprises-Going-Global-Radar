# LLM 分层接入（2026-10-20）

本分支（`feat/llm-wiring-20261020`）把运行时各层 LLM 真正接到默认界面，并修复 M2 摘要被静默丢弃的问题。所有调用仍遵守原分工：模型只做理解、摘要、改写；法规、日期、链接来自已核对语料，引用对齐不通过即丢弃模型输出。

## 各层状态

| 层 | 入口 | 默认是否调用 | 失败时 |
|---|---|---|---|
| 基础客户端 | `core/llm.py` | 配置 `MODEL_API_TOKEN` / `MODEL_API_BASE` / `MODEL_NAME` 后可用 | 返回 `meta.ok=false`，不抛异常 |
| 输入理解 | `modules/m15_router.py: parse_model()` | Gradio 新会话默认开启；SPA `/api/route` 默认 `use_llm=true` | 回落本地词典 |
| M1 卖家提示 | `core/llm.py: m1_tips()` | Gradio / SPA / CLI 均按开关调用 | 保留原始清单，无中文提示 |
| M2 变化摘要 | `core/llm.py: m2_summaries()` | 同上 | 使用确定性摘要/影响文本 |
| M3 动作改写 | `core/llm.py: m3_actions()` | 同上 | 使用规则抽取动作 |
| 两层召回 | `modules/recall_flow.py` | Gradio 会话「检索条文依据」；SPA 编号查询失败后的智能检索；CLI / 评测 | 确定性兜底 |
| 新法规发现 | `scripts/discover_new_laws.py` | 脚本；LLM 判定相关性 + 可选 Web Search | 如实标记未判定 |
| 数据翻译 | `scripts/enrich_cn.py` | 数据管线 | 不写回，保留原值 |

M4 是固定题干的历史回放，不实时调用 LLM；M5/M6/M7 为确定性规则。

## 默认行为

- **Gradio 聊天界面**：`ui_chat._new_session()` 在模型就绪时把 `context.use_llm` 设为 `True`。开关文案为「使用已配置模型理解输入与润色结果」；取消勾选后 M1/M2/M3 回到确定性结果。
- **SPA**：`web/js/api.js` 的 `/api/route` 默认 `use_llm=true`；`web/js/data.js` 为 `map` / `todo` / `timeline` 请求带 `use_llm=true`。未配置模型时后端立即降级，不阻塞页面。
- **CLI**：`m1_map.query`、`m2_timeline.query`、`m3_todo.query` 的 `use_llm` 默认仍为 `True`。
- **conversation**：`_call()` 只在 `context.use_llm=True` 且 `llm.is_ready()` 时把 `use_llm=True` 传给三个模块；否则不发起模型调用。

## 两层召回接入对话

`modules/recall_flow.py` 之前只挂在 CLI/评测，原因是它返回的是条文片段，不是 M1/M2/M3 的记录结构，且依赖本地条款库。本次补了两条产品入口：

1. **Gradio 会话**：新增 `recall` 意图，识别「原文 / 条文 / 条款 / 第 N 条 / 具体规定 / 怎么规定 / 法条」。命中后调用 `recall_flow.run()`，把 `retrieval.selected` 转成会话条目（保留 heading、正文、locator、law_id），并在结果中明确“片段不等于逐条适用性审核”。没有条款库时如实返回原因，不生成法律结论。
2. **SPA 条款检索**：`/api/search` 先按法规编号走 `law_store.retrieve()`；编号定位失败时自动把输入当自然语言问题走两层召回，搜索页显示“智能检索结果”。

两层召回内部仍是：路由 LLM 从编号目录选法规 → 检索 LLM 从候选切片选 ref → 代码按 ref 回填正文和 citation_map。模型只返回整数 ref，越界引用丢弃。

## M2 修复

模型实测会把完整事件键 `32025R0040|2026-08-12|适用` 缩写成 `32025R0040`。旧代码按完整事件键查找，导致摘要全部被丢弃，但 `meta.ok` 仍为 `True`。

`core/llm.py: parse_event_summaries()` 现在依次尝试：

1. 完整 `event_key` 精确匹配；
2. 前缀匹配（模型只写到日期）；
3. 同一法规下按模型输出顺序分配（同一法规多个日期时）。

只有键对齐，摘要和影响文本原样保留。`meta` 增加 `parsed` / `expected`，便于发现“模型成功但解析不到”的情况。
