# 出海合规雷达 · AI 全流程执行手册

> 版本：10.14 v3 ｜ 截止：2026-10-18 17:00  
> 定位：**全部工作交给 AI 执行**。本手册不含分工姓名，只写「做什么 + 怎么指挥 AI + 执行顺序 + 验收标准」。  
> 使用者：接手本项目的人，按章节顺序推进即可。

---

## 核心思路：AI 不是"帮手"，是"执行者"

本项目有 6 条工作线。其中 **约 80% 可以交给 AI 直接产出成品**，剩余 20% 是 AI 的结构性盲区（需要账号权限、需要人眼判断、需要真人操作屏幕）。

**先记住这条分界线**，后面所有步骤都基于它：

| 类别                | 具体内容                                  | AI 能否完成                       |
| ----------------- | ------------------------------------- | ----------------------------- |
| **A 类：AI 直接产出**   | 写代码、写脚本、写文档、做表格模板、生成配置、排查报错、生成测试题、写话术 | ✅ 能，且质量接近成熟工程                 |
| **B 类：AI 需要人喂输入** | 所有依赖「外部数据准确性」的工作：法规编号、生效日期、官方链接       | ⚠️ AI 只能当**线索生成器**，结论必须回官方源核实 |
| **C 类：AI 无法完成**   | 注册账号、点击部署按钮、登录提交作品、录制屏幕、真人试用反馈        | ❌ 必须真人                        |

> **最重要的认知**：AI 在 B 类里的表现是「**流畅但可能错**」。实测已证实 —— AI 会笃定地回答「儿童玩具须遵守 Directive 2009/48/EC」，而该指令**已被 Regulation (EU) 2025/2509 取代**。所以凡是法规编号、日期、数字，**AI 的话只能当线索**。

---

## 执行总顺序（照这个顺序跑，不要跳）

```
第 0 步：拿到钥匙（凭证）        ← 不完成，后面全部停摆
   ↓
第 1 步：验证数据拿得到          ← 决定走"在线抓取"还是"离线兜底"
   ↓
第 2 步：建数据资产（语料库）    ← 这是产品的"燃料"
   ↓
第 3 步：写代码（六个零件）      ← AI 主战场
   ↓
第 4 步：部署上线                ← 必须真人点按钮
   ↓
第 5 步：造证据（评测+试用）     ← 材料里所有数字的来源
   ↓
第 6 步：写材料                  ← 有数据才有材料
   ↓
第 7 步：提交                    ← 12:00 前完成，留缓冲
```

# 第 0 步：拿到钥匙（凭证）

## 要拿到的东西

| 编号  | 物品                  | 从哪拿            | 为什么必须                |
| --- | ------------------- | -------------- | -------------------- |
| 0.1 | 大模型平台 **API Token** | 平台「访问令牌」页新建    | **没有它，代码连不上模型，全队停摆** |
| 0.2 | 代码仓库地址（public）      | GitHub 新建仓库取链接 | AI 产出的代码要放这里         |
| 0.3 | 部署平台账号（能登录）         | 注册后确认可登录       | 最后上线要用               |
| 0.4 | 法律专业 MCP 接入凭证       | 资源平台申请         | 可选模块，**不阻塞主线**       |

## 怎么指挥 AI

**提需求的方式**（照着复制）：

```
我要注册某平台并生成 API Token，请给我逐步操作指引：
1. 从网站首页开始，每一步点哪里（用文字描述界面位置）
2. 「新建令牌」时权限应该勾哪几项、不要勾哪几项，说明每项的作用
3. 令牌生成后如何安全保存（哪些做法容易泄露）
4. 如何验证令牌可用（给一段最小的测试代码）
注意：我不懂技术，请用最通俗的话解释，每个术语都要说明。
```

**让 AI 写「安全存放配置」的代码**：

```
请写一份配置读取模块，要求：
- API Token 从环境变量读取，不写死在代码里
- 附一份 .env.example 模板（不含真实值）
- 附 .gitignore 配置，确保 .env 不会被提交到公开仓库
- 代码里加注释说明每一步，我要能看懂
```

## 验收标准

- [ ] Token 能用最小测试代码成功调用一次模型
- [ ] `.gitignore` 已排除配置文件
- [ ] 令牌**没有**出现在任何群聊、截图、代码里

## ⚠️ 红线

- 令牌等同于账号钥匙。**只私发，不进群，不截图，不写进代码。**
- 全部工作结束后立即删除令牌。

# 第 1 步：验证数据拿得到（最关键的一步）

## 为什么这一步决定成败

产品的燃料是欧盟官方法规数据。如果拿不到，后面六个零件全是空壳。**必须先验证，不要边写代码边赌。**

实测已知：直接请求官方站点会返回**空响应**（对方反爬）。所以这一步要跑通至少一条通路。

## 三条通路（按优先级依次试）

| 通路               | 做法                                    | 成功率            |
| ---------------- | ------------------------------------- | -------------- |
| **通路 A：官方 API**  | 使用官方提供的结构化数据接口（REST/SOAP），比爬网页友好得多    | 最高，首选          |
| **通路 B：模拟正常浏览器** | 设置 User-Agent、请求间隔 2 秒以上、限制并发为 1、失败重试 | 通常能通           |
| **通路 C：手动下载兜底**  | 手动下载官方文件，建成离线语料库                      | **一定能通**，最坏情况用 |

## 怎么指挥 AI

**第一步：让 AI 写探测脚本**

```
请写一个 Python 脚本，测试能否从某官方网站获取法规数据：
- 先试官方 API 接口，打印返回状态和数据结构
- 如果失败，自动降级为带浏览器头的普通请求
- 每次请求间隔至少 2 秒，不要并发
- 打印清晰的结果：成功拿到什么、失败报什么错
- 脚本要能直接运行，不要依赖我手动改代码

同时告诉我：如果两种方式都拿不到，还有哪些替代方案，按可行性排序。
```

**第二步：把失败结果原样贴回给 AI**

不管报什么错，**整段复制**给 AI，并说：

```
这是我运行的结果（粘贴原文）。
请判断：
1. 这是被反爬拦截、还是我代码写错了、还是网络问题？
2. 根据这个具体报错，下一步应该改什么？
3. 给我修改后的完整代码，不要只给片段。
```

**第三步：如果都失败，让 AI 写离线兜底方案**

```
在线抓取不可用，请改用离线方案：
1. 告诉我如何手动批量下载官方文件（给出具体步骤）
2. 写一个脚本，把这些本地文件解析成带元数据的结构化数据
3. 元数据字段必须包含：官方标题、官方编号、CELEX号、ELI标识、OJ出处、发布日期、生效日期、适用日期
4. 支持按类目检索
```

## 验收标准

- [ ] 三个类目各能拿到 ≥10 条法规数据
- [ ] 每条数据带官方链接
- [ ] 明确记录了「走的是哪条通路」

## ⚠️ 红线

- **不要自己去研究反爬技术细节**，把报错丢给 AI，让它给方案。
- 不要买代理服务 —— 这是公开数据，问题只是"不欢迎爬虫"，换个方式就能解决。

# 第 2 步：建数据资产（语料库）

## 要产出什么

一份结构化语料库，每条法规记录以下字段（**字段名不可改动**）：

```
序号 / 类目 / 法规中文名 / 官方标题（英文）/ 官方编号 / CELEX号 / ELI标识 /
官方链接（EUR-Lex）/ 来源类型 / OJ出处 / 生效日期 / 最新修订日期 /
链接可打开 / 编号核对 / 是否官方来源 / 核对状态 / 核对人 / 核对日期 / 备注／问题
```

其中「来源类型」的取值固定为：`官方原文（OJ）`、`官方整合版`、`官方摘要`、`非官方（第三方）`、`待确认`

## 怎么指挥 AI

**① 让 AI 生成核对表骨架（含下拉选项）**

```
请生成一个 Excel 文件，结构如下：
- 表头 18 列：序号、类目、法规中文名、官方标题（英文）、官方编号、CELEX号、
  ELI标识、官方链接（EUR-Lex）、来源类型、OJ出处、生效日期、最新修订日期、
  链接可打开、编号核对、是否官方来源、核对状态、核对人、核对日期、备注／问题
- 下列列加数据校验（下拉选择）：
  类目：儿童玩具、电子电器、纺织服装、其他
  来源类型：官方原文（OJ）、官方整合版、官方摘要、非官方（第三方）、待确认
  链接可打开：是、否、待查
  编号核对：一致、不一致、待查
  是否官方来源：官方、存疑、非官方
  核对状态：待核对、已核对、有问题
- 冻结首行首列，开启自动筛选
- 表头加粗、字号合适、列宽合理
```

**② 让 AI 写「官方来源判定规则」**

```
请写一份《官方来源判定指南》，用来说明什么样的链接才算「可引用的官方来源」。
要求：
1. 给出三条硬性判定条件（域名、法源层级、唯一标识）
2. 说明「官方原文」与「整合版」的区别，以及引用时该用哪个
3. 列举"不算官方来源"的情形（第三方数据库、律所解读、百科、AI 摘要）
4. 给出标准的链接获取动作步骤
5. 附一个「标识体系速查」：CELEX 号的构成规则、ELI 标识的结构
```

**③ 让 AI 做数据清洗**

```
我有一批抓取下来的法规文本（粘贴内容）。
请帮我：
1. 剥离网页导航栏、页脚、广告等噪声
2. 统一日期格式为 YYYY-MM-DD
3. 提取标题、编号、正文、发布机构
4. 输出为结构化 JSON，字段见下方
```

**④ ⚠️ 让 AI 做交叉验证（关键用法）**

```
请列出「出口欧盟的儿童玩具」需要遵守的法规清单。
注意：你给出的信息我会去官网逐条核实。请：
1. 每条给出官方编号和大致生效时间
2. 明确标注你不确定的部分
3. 特别说明：这条法规是否已被修订或取代
```

> **为什么这样问**：加最后一句「是否已被取代」，AI 才可能提示法规更替。**但即使它说了，也必须回官网核实。**

## 验收标准

- [ ] 三个类目各 ≥10 条，字段完整
- [ ] 每条都能点开官方链接
- [ ] 变更类事件（被取代 / 新修订 / 过渡期）已标注
- [ ] 至少有一条「非官方来源」的反面样例

## ⚠️ 红线

- ❌ 没有 CELEX 号或 ELI 链接的条目 **不许入库**
- ❌ 链接点不开的条目 **不许输出给用户**
- ❌ 不许把「整合版」当作唯一依据引用现行要求
- ✅ 所有没核实过的，标注「未核实」

## 💡 已发现的高价值素材

欧盟儿童玩具法规已更替：**Regulation (EU) 2025/2509** 于 2025-11-26 通过、2026-01-01 生效，将于 **2030-08-01 起全面取代** 沿用了十余年的 **Directive 2009/48/EC**。

**这个案例必须用上**，因为它是产品的核心论据：法规会变 → 卖家跟不上 → AI 答的是旧版。**设为对照演示的默认示例。**

# 第 3 步：写代码（六个零件）

## 零件清单与功能

| 零件 | 文件             | 干什么        | 人话解释                  |
| -- | -------------- | ---------- | --------------------- |
| ①  | `crawler.py`   | 抓取器        | 自动去官网把法规原文下载回来        |
| ②  | `database.py`  | 语料库        | 把法规存好，每条带编号/日期/链接标签   |
| ③  | `retriever.py` | 检索器        | 你说"儿童玩具"，它挑出相关法规（不全倒） |
| ④  | `llm.py`       | 大模型接入      | 把英文法规翻译+总结成人话         |
| ⑤  | `verify.py`    | **引用对齐** ⭐ | 每条输出必须挂官方链接，挂不上就不输出   |
| ⑥  | `app.py`       | 界面         | 用户看到的网页               |

> **零件 ⑤ 是产品的命根子**。前四个别人也能做，第 ⑤ 个决定了「答案可不可验证」。**这条永远不砍。**

## 怎么指挥 AI（核心方法）

### 方法一：一次给全上下文，别挤牙膏

**低效问法** ❌：「帮我写个爬虫」  
**高效问法** ✅：

```
【项目背景】
做一个「出海合规雷达」工具：用户输入商品类目+目标市场，输出适用法规清单、
近期法规变化、可执行待办清单，每条结论必须附官方原文链接。
技术栈：Python + Gradio（部署在魔搭创空间）
数据源：EUR-Lex 官方渠道

【硬性约束】
1. 大模型只负责「理解、归类、摘要、翻译」四件事
2. 抓取、URL 校验、引用对齐、缓存去重全部用确定性代码完成
3. 每条输出必须回挂官方链接，拿不到链接的内容一律不输出
4. 必须固定输出免责声明：「本清单仅供参考，不构成法律意见，请由专业人员复核」

【本期范围】
仅欧盟 1 个市场；仅 3 个类目（儿童玩具、电子电器、纺织服装）

【任务】
现在请写零件①抓取器 crawler.py，要求：
- 遵守 robots 协议，请求间隔 ≥2 秒，不并发
- 失败自动重试 3 次，指数退避
- 支持从本地文件兜底（在线失败时）
- 输出结构化 JSON，字段：官方标题、官方编号、CELEX号、ELI标识、OJ出处、发布日期、生效日期、适用日期、官方链接、正文
- 每行代码加中文注释，我要能看懂每一句在干什么
- 附一段「如何运行」的说明
```

请按下面的目录结构，一次性生成全部文件的框架代码：

# 第 4 步：部署上线

## 为什么这步 AI 干不了

部署需要在**账号持有人登录状态下，在网页上点击按钮**。AI 无法代劳。但 AI 可以：

- 写好全部配置文件
- 给出逐步操作指引
- 排查部署报错

## 怎么指挥 AI

```
我要把项目部署到魔搭创空间（免费托管平台），请给我逐步操作指引：
1. 从平台首页开始，每一步点哪里
2. 需要准备哪些文件、每个文件的作用
3. requirements.txt 应该怎么写（附完整内容）
4. 部署后如何拿到可访问的链接
5. 如果部署失败，常见原因有哪些、怎么排查
我不懂技术，请用最通俗的话说，每个术语都要解释。
```

**部署报错时**：

```
部署失败了，报错如下（粘贴）：

我的 requirements.txt 内容（粘贴）：

请判断：是依赖写错了、配置文件有问题、还是平台限制？
给出修改后的完整文件内容。
```

## 验收标准

- [ ] 链接是 HTTPS 且可直接访问（无痕窗口能打开）
- [ ] 三个类目能端到端跑通
- [ ] 手机浏览器也能打开

## ⚠️ 红线

- 部署按钮**必须账号本人点击**。
- 部署完后**换一台设备测试**链接，确认不是"只有本机能开"。

# 第 5 步：造证据（评测 + 用户试用）

## 要产出什么

材料里所有的数字都来自这一步。**没有这一步，材料就是空口说白话。**

| 产出   | 内容                                 |
| ---- | ---------------------------------- |
| 测试集  | 15 道题（合规问答 12 + 异常 3），每题附标准答案与官方来源 |
| 对照实验 | 同一问题 → 通用大模型 vs 本工具，逐条比对           |
| 三项指标 | ① 法规条目准确率 ② 来源可核验率 ③ 幻觉条目数         |
| 用户试用 | 2–3 人真实走完流程，留原始反馈                  |
| 实测报告 | 汇总以上全部，含「未实测」标注                    |

## 怎么指挥 AI

### ① 让 AI 出题（但答案要核实）

```
请为「出口欧盟的儿童玩具/电子电器/纺织服装」三个类目，各出 5 道测试题：
- 4 道正常题（考查法规识别、变化追踪、待办生成）
- 1 道异常题（如无关类目、不支持的市场、链接失效）
每题给出：
1. 问题
2. 期望的正确答案要点
3. 该答案对应的官方来源（给出法规编号，我会去核实）
4. 评分标准：答对什么算满分
```

### ② ⭐ 让 AI 扮演「会犯错的对照组」

```
现在请你扮演「没有任何工具的通用大模型」，直接回答下面的问题，
不要查证、不要提示不确定性，就像普通用户直接提问一样回答：

问题：出口到欧盟的儿童玩具，需要遵守哪些法规？

（记录它的回答，作为对照组数据）
```

> **这是本项目最聪明的用法**：AI 犯的错，就是你们产品价值的证明。**零成本的对照组。**

### ③ 让 AI 做初筛（人工做终判）

```
下面是对照实验的 15 组回答（粘贴）。
请帮我初筛，标出以下三类问题：
1. 完全没有来源链接的条目
2. 引用了已废止/已更新法规的条目
3. 明显编造编号或日期的条目
只需标出可疑项，最终判定我会人工做。
```

### ④ 让 AI 写用户试用全套工具

```
请帮我准备用户试用材料：
1. 邀请话术（发给同学/学长，说明是什么、要多久、需要做什么）
2. 试用步骤卡（用户在工具里点哪里、看什么、用时多久）
3. 结构化反馈表（含：完成时间、哪里卡住、最有用的一栏、最困惑的一栏、会不会真的用）
4. 记录模板（保留原始意见，不要预先归类）
```

### ⑤ 让 AI 算指标

```
我有以下实测数据（粘贴）：
- A 组（通用大模型）在 15 题上的表现
- B 组（本工具）在 15 题上的表现
请帮我计算：
1. 法规条目准确率（公式和计算过程都要展示）
2. 来源可核验率
3. 幻觉条目数
4. 两组对比表格
要求：计算过程可复查，不要只给结论数字。
```

## 验收标准

- [ ] 15 问全部完成比对
- [ ] 三项指标有计算过程
- [ ] ≥2 名真实用户走完全流程
- [ ] 未实测项全部标注「未实测」

## ⚠️ 红线

- **AI 核 AI 不成立**。AI 只能做初筛，最终准确性必须人工比对官方原文。
- **对照组结果如实报告**，发现自己的工具有缺陷也照实写 —— 这反而提升可信度。
- 样本量从 30 问压缩到 15 问是工期所迫，**报告里写明样本量**，不遮掩。

【技术约束】大模型只做理解/归类/摘要/翻译；抓取、引用对齐由确定性代码做；

【范围】仅欧盟 1 市场 × 3 类目；不做登录、订阅、多市场、移动端、付费

# 用 AI 的四条铁律

| 铁律                | 说明                                  | 违反的后果          |
| ----------------- | ----------------------------------- | -------------- |
| **① AI 做执行，人做判断** | 编码、写稿、生成模板交给 AI；法规准确性、范围取舍、验收判定必须人工 | 会把错误内容直接提交上去   |
