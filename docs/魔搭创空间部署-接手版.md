## 1. 接手账号后先确认 7 件事

### 1.1 登录并确认用户名

打开 https://modelscope.cn 登录，右上角头像 → 个人主页，确认用户名。

也可以用令牌确认：

```powershell
$env:MODELSCOPE_API_KEY = "<你的访问令牌>"
curl.exe "https://modelscope.cn/openapi/v1/users/me" -H "Authorization: Bearer $env:MODELSCOPE_API_KEY"
```

或：

```powershell
.\.venv\Scripts\python.exe scripts\modelscope_studio.py check `
  --studio zhanxy2551/ComplianceRadar-v2
```

如果用户名**不是** `zhanxy2551`，你无法直接推这个空间。两个选择：

1. 让原负责人把空间 **Fork / 转移** 到你的账号；
2. 在你的账号下新建空间（本文第 7.4 节），用新空间作为比赛提交地址。

### 1.2 生成访问令牌

https://modelscope.cn/my/myaccesstoken → 新建令牌 → 勾选 **Git 写权限 / Studio 读写**
（至少要能 push `master`、调用 deploy 和变量接口）→ 复制一次保存。

- 国内站 `modelscope.cn` 和国际站 `modelscope.ai` 的令牌**不互通**；
- 令牌只在命令行环境变量里用，不要写进 `ms_deploy.json`、`.env.example`、README 或 Git remote URL；
- 接手别人账号时，先**删除旧令牌**，再建自己的。

### 1.3 核对空间设置

在空间页面 → 设置，确认：

- SDK：Gradio
- 版本：**6.2.0**（本项目在 6.2.0 上验证；不要随手升到 6.29）
- 基础镜像：`ubuntu22.04-py311-torch2.9.1-modelscope1.35.0`
- 资源：`platform/2v-cpu-8g-mem`（当前唯一免费 CPU；见下方说明）

**重要**：`https://modelscope.cn/api/v1/studios/deploy_schema.json` 是静态 schema，
可能落后于线上。请以带鉴权的实时接口为准：

```bash
curl --noproxy '*' "https://modelscope.cn/openapi/v1/studios/hardware?sdk_type=gradio"
```

2026-10-20 实测只返回：

```json
{"name":"platform/2v-cpu-8g-mem","resource_type":"free"}
```

所以根目录 `ms_deploy.json` 里的 **8g 是当前正确的**，不要按静态 schema 改成 16g。
如果以后平台上线了新的免费规格，以同一个接口返回的 `name` 为准。

### 1.4 检查空间变量与 Secret

空间设置 → 变量 / Secret，至少确认这些 key 存在（值不要截图外传）：

| key | 类型 | 用途 |
|---|---|---|
| `MODEL_API_TOKEN` | Secret | 大模型 API Token（当前本地是 DeepSeek） |
| `MODEL_API_BASE` | 变量 | `https://api.deepseek.com` |
| `MODEL_NAME` | 变量 | `deepseek-flash` |
| `CR_UI` | 变量 | `spa`（强制新界面） |
| `ASR_BACKEND` | 变量 | 首次部署填 `off`，先把文字链路跑通 |
| `GRADIO_TEMP_DIR` | 变量 | `/mnt/workspace/tmp`（可选） |

加/改用的命令见第 6 节。

### 1.5 接管安全

- 改密码、绑定自己的邮箱/手机；
- 删除旧令牌、旧 SSH key、旧协作者；
- 轮换 `MODEL_API_TOKEN`（DeepSeek 控制台里作废旧 token，换新）；
- 旧空间 `master` 里有一个 7.3MB 的源码 ZIP，我已下载检查：**没有 `.env`、没有命中常见 token 模式**；
  但历史里的 ZIP 仍可被公开访问，仍建议把旧 token 全部作废；
- 检查空间变量的值是否还是原负责人的个人 key。

### 1.6 确认线上实际版本

空间仓库的 `sbuild-*` 分支是平台构建快照。当前快照没有 `web/` 和 `web_app.py`，
说明线上不是本次要部署的 SPA 版。部署后要重新确认。

### 1.7 确认你能看到“部署/重新部署”和“日志”

空间页面 → 设置/部署记录。如果账号没有写权限，先解决权限，再继续。


注意：部署令牌和推理令牌可以是同一个，但权限要够；模型 ID 必须在该账号下可用。

### 6.4 语音识别怎么办

首次部署建议 `ASR_BACKEND=off`，先把文字链路跑通。之后要开语音，有三条路：

1. **云端转写**：配 `ASR_BACKEND=cloud`、`ASR_API_BASE`、`ASR_API_KEY`、`ASR_MODEL`；
   需要你确认服务支持 OpenAI 兼容的 `/audio/transcriptions`。
2. **本地 sherpa-onnx**：设 `ASR_BACKEND=engine`、`ASR_ENGINE_AUTO_DOWNLOAD=1`；
   首次启动会下载 Linux 引擎和 SenseVoice 模型，慢且依赖外网。
   也可以预先准备好 Linux 版 `models/sherpa-onnx/` 再上传，但不要上传本机 447MB 的 Windows 二进制。
3. **旧 Whisper 兜底**：在 `requirements.txt` 加回
   `faster-whisper>=1.2.0,<2` 和 `av>=11,<19`，上传
   `models/faster-whisper-base/`（145MB，走 LFS），设 `ASR_BACKEND=local`。

不配置时语音按钮会置灰并给出原因，文字功能不受影响。

## 7. 推送代码

### 7.1 推荐：用脚本

先干跑，确认账号/空间/文件清单：

```powershell
.\.venv\Scripts\python.exe scripts\modelscope_studio.py push `
  --studio zhanxy2551/ComplianceRadar-v2 `
  --dir dist\modelscope-deploy
```

脚本会：

1. 用令牌临时克隆空间 `master`（`GIT_LFS_SKIP_SMUDGE=1`，不拉旧模型）；
2. 保留平台的 `.gitattributes`（LFS 规则）；
3. 删掉旧的应用载荷（README、旧 ZIP），换成 `dist/modelscope-deploy`；
4. `git add -f runtime-assets/law-store.bundle`（项目 `.gitignore` 默认忽略它）；
5. 打印变更清单；**不加 `--yes` 不会提交/推送**；
6. 加 `--yes` 后提交并推送 `HEAD:master`，**不使用 force**；
7. 出错时自动打码令牌。

确认后：

```powershell
.\.venv\Scripts\python.exe scripts\modelscope_studio.py push `
  --studio zhanxy2551/ComplianceRadar-v2 `
  --dir dist\modelscope-deploy --yes
```

### 7.2 手动 Git（想学细节）

```powershell
$owner="zhanxy2551"; $repo="ComplianceRadar-v2"
$token=$env:MODELSCOPE_API_KEY
$url="https://oauth2:$token@www.modelscope.cn/studios/$owner/$repo.git"

$tmp="$env:TEMP\cr-studio-deploy"
if (Test-Path $tmp) { Remove-Item -Recurse -Force $tmp }
$env:GIT_LFS_SKIP_SMUDGE="1"
git -c http.proxy= -c https.proxy= clone --branch master $url $tmp
```

进入 `$tmp`：

- 保留 `.gitattributes`；
- 删除旧的 `README.md`、`出海合规雷达_项目源代码.zip` 等；
- 把 `dist\modelscope-deploy\` 里的内容复制进来；
- 确认根目录直接是 `app.py`、`web/`、`web_app.py`，不是多一层文件夹。

```powershell
git add -A
git add -f runtime-assets/law-store.bundle
git status --short
git diff --cached --stat
git -c user.name="ComplianceRadar Deploy" `
    -c user.email="deploy@compliance-radar.local" `
    commit -m "Deploy SPA build from <源码提交号>"
git -c http.proxy= -c https.proxy= push origin HEAD:master
```

被拒绝时：

- **不要 `--force`**；
- 重新 fetch/merge 后重推；
- 如果远端有平台专用文件（LFS 模型、Dockerfile），先看清再决定是否保留。

### 8.2 状态

| 状态 | 含义 | 动作 |
|---|---|---|
| Building | 构建中 | 等，查构建日志 |
| Running | 运行中 | 进入验收 |
| Failed | 启动失败 | 查运行日志 |
| Sleeping | 长时间无访问休眠 | 打开页面唤醒 |
| Stopped | 已停止 | 重新部署 |

### 8.3 日志

```powershell
.\.venv\Scripts\python.exe scripts\modelscope_studio.py logs `
  --studio zhanxy2551/ComplianceRadar-v2 --type run --tail 200
```

构建日志把 `--type run` 换成 `--type build`。

正常应看到：

```text
[LAW] Public clause database verified and prepared
[ASR] ...（或语音关闭提示）
[UI] SPA mount failed; falling back to the Gradio shell   # 不应出现
Running on local URL:  http://0.0.0.0:7860
```

构建 3–10 分钟属正常；免费 CPU 更慢。免费实例长时间无访问会休眠；
打开空间页面即可唤醒，比赛/评审前先手动打开一次。

**注意“旧快照重复构建”**：如果状态 Running 但页面还是旧版，
检查最新 `sbuild-*` 分支/构建记录里的文件是否包含 `web/` 和 `web_app.py`。
点“重新部署/重建”，不要只重启旧镜像。

## 9. 上线验收清单

打开空间页面，逐项做：

1. 首屏是 SPA（有“最近检查”/法规时效卡片），不是旧 Gradio 聊天页。

| 现象 | 原因 | 修复 |
|---|---|---|
| 白屏 / 404 | 包缺 `web/` 或 `web_app.py`；或 `web_app.install` 失败 | 重新打包；查日志 `[UI] SPA mount failed` |
| 页面是旧 Gradio | 构建用了旧快照 / 未重新部署 | 检查 sbuild 文件；重新部署 |
| `ModuleNotFoundError` | `requirements.txt` 缺依赖 | 补依赖后重推 |
| Gradio/pydantic 版本冲突 | 平台 SDK 已装 Gradio，requirements 又 pin 了一次 | 删掉 `requirements.txt` 里的 `gradio==6.2.0`，让 SDK 提供 |
| `FileNotFoundError: data/...` | 打包漏了运行数据 | 用 `prepare_modelscope_deploy.py` 重建 |
| 条款检索报“条款库未配置” | bundle/manifest 缺失或不匹配 | 检查 `runtime-assets/` 与 `data/law_store_manifest.json` 的 SHA/大小 |
| 启动卡住/超时 | `ASR_ENGINE_AUTO_DOWNLOAD=1` 在下载语音引擎 | 设 `ASR_BACKEND=off`，先保文字 |
| 内存不足/OOM | 免费 8GB，pandas/lxml 峰值 | 减少并发；或按平台指引升级资源（先确认费用） |
| Git 认证失败 | 令牌错/过期/国际站令牌 | 用对应站点的令牌；确认 `oauth2:` 格式 |
| Git 连接失败 | 本机 7897 代理没开 | `git -c http.proxy= -c https.proxy=` 或清空代理环境变量 |
| push 被拒绝 | 远端有新提交 | fetch/merge 后重推，**不要 force** |
| LFS 报错 | 大文件未走 LFS | `git lfs install`；检查 `.gitattributes` |
| 端口冲突 | 应用没监听 0.0.0.0:7860 | 本项目默认 7860；不要设成本机临时端口 |
| 模型 401 | Secret 没配/旧 token 已作废 | 更新 `MODEL_API_TOKEN` 后重新部署 |

## 11. 回滚

- 保留本次部署前的 `sbuild-*` 分支和源码 ZIP；
- 每次部署前保存 `dist/ComplianceRadar-modelscope-*.zip`；
- 需要回滚时，把旧版本文件作为一个**新提交**推回 `master`，再部署；
  不要 force push，不要删除当前工作目录；
- 空间的 `/mnt/workspace` 数据、变量和 Secret 不会随源码回滚自动恢复，需单独确认。
