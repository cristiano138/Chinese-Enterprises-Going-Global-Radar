# 时效性监控 · 设计说明与运行口径

版本：2026-10-19 ｜ 状态：两层检查已跑通，定时方案已落地（北京时间 19:00 / 22:00）

## 1. 一句话

链接级回答「官方页面是否可达、有没有取到内容」；字段级回答「官方修订日期/生效日期/最新文档号有没有变」。
两层都不替代人工核对，也不把「页面变了」说成「法规条文变更」。

## 2. 监控对象

语料表 86 行法规，去重后共 **115 个官方链接**：

| 来源 | 数量 | 检查方式 |
|---|---|---|
| eCFR（美国） | 57 | 优先查 eCFR 官方 versioner API（结构化修订历史）；API 不可用时退回人类页面 |
| EUR-Lex 官方链接（欧盟） | 29 | 直接 GET 页面 |
| ELI 永久标识（欧盟） | 29 | 直接 GET 页面 |

> 早期文档写「86 条官方链接」，是因为当时 `URL_FIELDS` 误写成「ELI链接」，29 条 ELI 永久标识从未被核验。
> 修正后是 115 个去重链接。86 是法规行数，不是链接数。

## 3. 链接级：`scripts/check_freshness.py`

数据流：

```
语料 CSV（官方链接 + ELI标识）
    │  并发 8 路，单链 30s 超时，只读前 128KB 算 sha256
    ▼
data/freshness_log.jsonl     每链接每次一行（含 run_id）
data/freshness_runs.jsonl    每次运行汇总一行
data/freshness_latest.json   最新态（UI 只读）
```

口径（2026-10-19 修正）：

| kind | 含义 | 是否算已核验 |
|---|---|---|
| `ok` / `content_verified` | HTTP 成功且响应体非空 | 是 |
| `empty_content` | HTTP 成功但响应体为空（EUR-Lex 实测 202 空体） | 否，不判死链 |
| `rate_limited` | 重试后仍被官方 429 限流 | 否，不判死链 |
| `link_error` | 4xx/5xx（非限流） | 否，待人工复核 |
| `net_error` | 本机网络未连通 / SSL 握手失败 | 否，不判死链 |

`changed` 只有在**同一来源**（HTML 或 eCFR API）的两次非空哈希不同时才为真。
空响应哈希不参与比对，来源切换也不报变更。

eCFR 页面在自动化访问下会返回 429/503；脚本优先调用官方
`https://www.ecfr.gov/api/versioner/v1/versions/title-{N}.json?part={P}`，
用修订历史生成稳定指纹。EU 页面返回 202 空响应时，权威变更信号由字段级 SPARQL 提供。

代理策略：

- 默认 `--proxy auto`：先探测环境代理端口，不可达自动切直连并写入运行日志；
- `--proxy direct`：强制直连；`--proxy http://host:port`：强制指定代理。
- 代理 URL 在日志中脱敏，不打印凭据。

## 4. 字段级：`scripts/check_metadata_freshness.py`

对 `laws` 表 86 条法规逐条查官方接口，比对并回写：

- EU：`last_modification_date`、`in_force`、`latest_amendment_celex`、`latest_corrigendum_celex`
- US：`latest_fr_document_number`、`fr_effective_on`、`official_title`、`part_status`、`latest_amendment_date`
- 派生：`effective_status_detail`
- 脏数据（占位日期、格式错误编号）拒绝写入，只记日志
- 未来 90 天内的生效/到期节点进入 `upcoming_deadlines`

输出：

```
data/metadata_check_log.jsonl    追加，只记变化/被拒绝的字段
data/metadata_check_latest.json  覆盖，当次汇总 + failed + changes[].law_id
```

写库前备份策略：

- 手动运行默认 `--backup always`（时间戳备份）；
- 定时任务用 `--backup daily`：每天最多一份 `*-freshness` 备份，只保留最近 2 份；
- 正式库约 2.23GB，不建议每次全量复制。

## 5. 定时：北京时间每天 19:00、22:00

| 方案 | 文件 | 说明 |
|---|---|---|
| Windows 计划任务（主） | `scripts/install_freshness_schedule.ps1` | 注册任务 `ComplianceRadar-Freshness`，两个每日触发 19:00 / 22:00；错过触发补跑；单步超时 180 分钟，任务总时限 300 分钟 |
| GitHub Actions（备） | `.github/workflows/freshness-check.yml` | UTC `0 11,14 * * *` = 北京时间 19:00 / 22:00；CI 只跑链接级，无数据库时字段级记 skipped |
| 统一入口 | `scripts/run_freshness_checks.py` | 依次跑两层，写 `data/freshness_run_latest.json` / `freshness_run_log.jsonl` |

定时配置以 `data/freshness_schedule.json` 为准（`timezone=Asia/Shanghai`, `times=[19:00,22:00]`）。
本地注册：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_freshness_schedule.ps1
powershell -ExecutionPolicy Bypass -File scripts\install_freshness_schedule.ps1 -RunNow
powershell -ExecutionPolicy Bypass -File scripts\install_freshness_schedule.ps1 -Uninstall
```

### 手动补跑 / 排查

```bash
# 两层都跑（正式写库，备份策略每天最多一份）
python scripts/run_freshness_checks.py --proxy auto

# 只跑字段级，先演练
python scripts/check_metadata_freshness.py --dry-run --only US --limit 3 --proxy auto

# 只跑链接级，不写文件
python scripts/check_freshness.py --dry-run --proxy auto

# 查看最近运行
python -c "import json;print(json.load(open('data/freshness_run_latest.json',encoding='utf-8'))['steps'])"
```

若官方接口返回 403/429，先确认本机代理是否可用：
`--proxy auto` 会自动探测；Clash 未启动时会直连并在运行日志里记录 fallback。

## 6. 前端只读契约：`core/freshness.py`

前端改版分支只调用 `core.freshness.summarize()`，不自己算口径：

- 最近检查时间、距今天数、是否过期（默认 24h，可用 `FRESHNESS_STALE_HOURS` 覆盖）
- `total / content_verified / empty_content / rate_limited / link_error / net_error / changed`
- 待复核链接列表、最近两次运行
- 下一次计划时间（按 19:00 / 22:00 计算）
- 没有记录时 `first_run=True`，首页应切教程态，不显示空仪表盘

## 7. 与红线的关系

- 只访问官方公开链接与官方 API；
- 核验结果只是「链接/字段状态证据」，不构成法规结论；
- 结果如实显示核验时间与异常数；失败、空响应、限流都不遮掩；
- 前端不得显示「重新检查」按钮（检查由后台定时执行）。
