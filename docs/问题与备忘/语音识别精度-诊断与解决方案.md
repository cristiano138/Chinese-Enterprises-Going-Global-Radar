# 语音识别精度不高：诊断与解决方案

> 范围：M1.5-V 语音输入链路（`app_main.py` 录音 → `core/asr.py` 转写 → `modules/m15_router.py` 路由）
> 结论时间：2026-10-18

---

## 0. 一句话结论

精度不高**不是单一模型问题**，是四层叠加：

1. **解码参数刻意求快** —— `beam_size=1` 把 faster-whisper 的默认 5 降到贪心解码；
2. **领域词零偏置** —— 项目词表极小且封闭（7 品类 + 2 市场），却一个词都没喂给模型；
3. **下游零容错** —— 路由用精确子串匹配，一个错字就让整个槽位归零；
4. **没有置信度、没有纠错闭环** —— 错得理直气壮，用户只能整句重说。

其中第 3 条是**放大器**：它把每一处 1 个字的转写误差放大成 100% 的业务失败。所以修复顺序应该是
「先让错字不致命」→「再让错字变少」→「最后才谈换模型」。

---

## 1. 先定义"精度"：本项目真正的 KPI 不是 CER

`modules/m15_router.py:240-277` 的 `parse_local()` 用**精确子串匹配**（`w in blob`）从
`MARKET_WORDS` / `CATEGORY_WORDS` 里取品类和市场。

> 例：用户说「我要把**毛绒玩具**卖到**德国**」
> - ASR 输出「我要把**猫绒玩具**卖到**德国**」
> - 通用 CER：1/14 ≈ 7%，看起来"还行"
> - 槽位准确率：品类从命中变**未命中**，用户看到「没识别出品类」→ **业务失败**

因此：

| 指标 | 现状感知 | 优化收益 |
| --- | --- | --- |
| 通用字错率 CER | 用户听不出来 | 中 |
| **槽位准确率（品类 × 市场）** | 用户直接看到"识别不出" | **高** |
| 幻觉率（输出词表外的通顺废话） | 用户被误导，最危险 | 最高优先级 |

**所有改动都应以「槽位准确率」和「幻觉率」验收，而不是 CER。**

## 2. 代码级定位

| # | 现象 | 证据 | 影响 | 修复成本 |
| --- | --- | --- | --- | --- |
| 1 | 贪心解码 | `core/asr.py:380` `beam_size=1`（faster-whisper 默认 **5**） | 中文同音字/近音字明显增多，是当前最"白送"的精度损失 | 改 1 个数字 |
| 2 | 模型偏小 + int8 | `core/asr.py:73` 默认 `small`；`:369` `cpu/int8`；本机已下 464MB 的 `faster-whisper-small` | small 只有 466M 参数，中文短句 + 专业词本就弱；int8 再让一点 | 中（换模型/换引擎） |
| 3 | 无热词、无 initial_prompt | `core/asr.py:379-382` 只传 `language/beam_size/vad_filter/condition_on_previous_text` | 模型不知道「毛绒玩具」「食品接触材料」「GPSR」「EN 71」，必然写成同音错字 | 低（词表本来就有） |
| 4 | VAD 默认参数切句 | `:380` `vad_filter=True` 未传 `vad_parameters`，走默认 `threshold=0.5 / min_silence=2000ms / speech_pad=400ms` | 用户按下按钮立刻说话，句首/句尾被 VAD 咬掉；短句（3-5s）尤其明显 | 低 |
| 5 | 置信度未回传 | meta 固定六字段 `core/asr.py:419-420`，无 confidence；`app_main.py:1105-1112` 只显示"语音转写" | 用户无法判断该不该改字；低置信度结果与高置信度结果长得一模一样 | 低 |
| 6 | 云端无 prompt、无真降级 | `:308-342` 只发 `model/language`；docstring 写"任一失败自动降级"，但 `_transcribe_work:387-412` 选定后端失败即返回错误，**不会换本地重试** | 云端 5xx 时用户体验 = "语音坏了"，而本地明明可用 | 低 |
| 7 | 60s / 45s 硬上限 | `:86-88` `MAX_AUDIO_SECONDS=60`、`TRANSCRIBE_TIMEOUT=45.0` | 本地 small 首次加载 2-8s，长音频接近超时 → 报"转写超时"，被理解成"识别不出来" | 低 |
| 8 | 无音频前置质检 | `_read_wav:235-289` 只校验格式/大小/时长，不看音量 | 太小声/太远时 Whisper 会"幻听"出一段通顺但无关的话，`MIN_CHARS=2` 拦不住，直接进路由 | 低-中 |

## 3. 解决方案

### P0 · 半天，只改参数与词表（不动架构）

**A. 解码参数拨回正常档**

```python
# core/asr.py  _transcribe_local()
segments, info = model.transcribe(
    io.BytesIO(audio),
    language=lang,
    beam_size=5,                    # 5（默认）→ 原为 1，贪心
    best_of=5,
    temperature=0.0,                # 固定贪心温度，关掉 0.0→1.0 的 fallback 链
    condition_on_previous_text=False,   # 短句保持 False，避免错误传播（现有设置是对的）
    vad_filter=True,
    vad_parameters=dict(
        threshold=0.35,                 # 默认 0.5 对安静麦克风偏严
        min_silence_duration_ms=500,    # 默认 2000，短句会被过度切分
        speech_pad_ms=500,              # 默认 400，给句首句尾多留一点
    ),
    hotwords=HOTWORDS,              # 见 B
    initial_prompt="以下是普通话口述的商品合规需求，涉及品类、目标市场与法规名称。",
)
```

> `temperature=0.0` 的取舍：默认 fallback 链在解码失败时会升到高温度采样，产出"通顺但错"的文本，
> 且调用方看不出异常。宁可返回空 + 低置信度，也不要幻觉。质量阈值保留
> `compression_ratio_threshold=2.4` / `log_prob_threshold=-1.0` 用于过滤。

**B. 从现有词表自动生成热词（不硬编码，避免漂移）**

```python
# core/asr.py —— 单一事实来源仍是 m15_router
def _build_hotwords():
    from modules import m15_router as R
    words = []
    for ws in R.CATEGORY_WORDS.values():
        words += ws
    for ws in R.MARKET_WORDS.values():
        words += ws
    words += ["GPSR", "CE 认证", "EN 71", "ASTM F963", "CPC 证书", "FDA", "CPSC", "REACH"]
    # 去重、去单字、限长（hotwords 过长会反向干扰）
    return "、".join(dict.fromkeys(w for w in words if len(w) >= 2))[:800]
```

**C. 置信度透出（扩 meta 七字段）**

```python
segs = list(segments)
text = "".join(s.text for s in segs).strip()
probs = [s.avg_logprob for s in segs if s.avg_logprob is not None]
no_speech = max([s.no_speech_prob for s in segs] or [0.0])
confidence = 0.0 if not probs else max(0.0, min(1.0, math.exp(sum(probs) / len(probs))) * (1 - no_speech))
```

- `meta["confidence"]` 进 UI：`< 0.6` 时回声块变黄，文案"可能听错，请核对品类和市场"。
- 同步改 `scripts/selftest_voice.py`（它断言 meta 键集，`:56` 附近），否则自检直接红。

**D. 云端路径补齐**

- 请求体加 `prompt`（同 B 的热词串）、`temperature=0`、`response_format=verbose_json`；
- `_transcribe_work` 里加**真降级**：cloud 抛 `_ASRFailure` 且本地可用 → 用 local 重试一次，
  `meta["backend"]` 记 `cloud→local`，让 README 里"任一失败自动降级"名副其实。

### P1 · 1-2 天，词表约束纠错（ROI 最高）

新增 `core/asr_lexicon.py`：**只做"把错字纠正到封闭词表内的合法值"，不做任何补全**。

```python
def correct(text: str) -> tuple[str, list[dict]]:
    """返回 (纠正后文本, 纠正记录[{"from","to","reason"}])。

    守则（红线，与项目"识别依据可追溯"一致）：
      1. 只替换、不新增 —— 不允许把"玩具"扩写成"儿童玩具和电子电器"；
      2. 必须唯一候选 —— 有歧义就不动；
      3. 必须可回溯 —— 每条替换在 UI 回声块里显示「已按词表纠正 猫绒玩具 → 毛绒玩具（同音）」；
      4. 长度 ≥2 才参与，单字（"鞋"→"血"）风险太高；
      5. 距离上限：同音（无声调拼音相等）或编辑距离 ≤1，其余不动。
    """
```

匹配策略（按强度递减）：

| 策略 | 例 | 说明 |
| --- | --- | --- |
| 完全同音（无声调） | 猫绒玩具 → 毛绒玩具 | `pypinyin(lazy_pinyin, style=NORMAL)` |
| 编辑距离 ≤1 | 蓝牙耳记 → 蓝牙耳机 | 纯 str 操作，无需依赖 |
| 子串包含 + 拼音前缀 | 儿童毛绒 → 毛绒 | 仅在词表命中数为 0 时兜底 |

实现注意：

- `pypinyin` 是纯 Python 轻依赖，放进 `requirements-asr.txt`（可选项），缺失时自动退化为
  编辑距离-only，不破坏"不装也能跑"的约束；
- 纠正发生在 `normalize()` **之后**、进入路由**之前**，且在 `_cache_put` 之前，
  保证缓存里存的是纠正后文本；
- 纠正记录必须一起返回，不允许"静默改字"。

**为什么这一步最值钱**：它把"1 个错字 = 100% 业务失败"变成"1 个错字 = 无感"，
而且完全确定性、可审计、不花一次模型调用、不碰隐私边界。

### P2 · 1 周，换中文专用引擎（治本）

Whisper 在中文长音频/真实场景上的劣势是公开数据：FunASR 官方 184 条真实中文音频实测
CER **SenseVoice-Small 7.81%**、Paraformer-Large 10.18%，而 **Whisper-large-v3 20.02%**；
同时 SenseVoice 在 **CPU 上 17x 实时**（比 Whisper 在 GPU 上还快）。
对本项目"无密钥、纯 CPU、短句、领域词密集"的场景，这是"更准且更省"的组合。

落地方式（不动上层）：

```python
# core/asr.py 三级后端 → 四级
# ① cloud → ② local(whisper) → ③ funasr → ④ off
# available() 里加 _funasr_importable()；_transcribe_work 里加分支
# 模型：SenseVoiceSmall（推荐，带标点/ITN）或 paraformer-zh（原生 hotword 参数，硬偏置比 prompt 更强）
```

若暂时不上 FunASR，Whisper 路线的最低要求是 `small → medium`，且必须同时：

- 放宽 `TRANSCRIBE_TIMEOUT`（medium 在 CPU 上 60s 音频约 40-60s，当前 45s 会卡在超时线上）；
  或按 VAD 切成 ≤15s 分片逐片转写再拼接；
- 确认 `MAX_CONCURRENT=2` 在 CPU 抢占下的实际排队表现（两个 medium 并发会比 45s 更久）。

### P3 · 体验闭环（配合 P0/P1 一起上）

1. **音频前置质检**（`_read_wav` 之后，纯 PCM 计算，零依赖）
   - 时长 < 1s → "没录到，请按一下开始录音再说"
   - 峰值 < -30 dBFS 或 RMS < -45 dBFS → "太小声，请靠近麦克风"，**不发模型**（挡掉最坏情况的幻觉）
   - 削波比例 > 5% → "爆音了，请离远一点"
2. **服务端增益归一化**：对 16-bit PCM 做线性增益到峰值 -3 dBFS（`_read_wav` 已有完整解析，改造成本低），
   对手机/笔记本内置麦的拾音差异耐受度提升明显。
3. **n-best 候选 chips**：只展示"与词表有差异"的候选（2-3 个），点击替换，避免把用户推进选择困难。
4. **长音频分片**：>20s 时按 VAD 切分，逐片转写，顺带解决超时。

## 4. 怎么证明有效：先建 30 条评测集（半天，必须做）

没有基线，"变准了"只是感觉。

- **素材**：30 条真实口述（本地录，不进仓库），覆盖 7 品类 × 2 市场 + 5 条范围外（日本/钢材）+ 5 条含英文词
- **标注**：每条标 `品类 / 市场`
- **指标**：`CER`、**`槽位准确率`**、`幻觉率（输出含词表外品类）`、`P95 延迟`
- **脚本**：`scripts/eval_asr.py`，跑"改前/改后"对比表；音频不入库，只在本地跑（不进 CI）
- **验收线建议**：槽位准确率 ≥ 95%，幻觉率 = 0，P95 延迟 ≤ 3s

## 5. 红线（与项目既有约束对齐）

- **纠错不是补全**：只允许替换、不允许新增槽位；所有替换在 UI 可回溯（守住"识别依据可追溯"）
- **hotwords 有副作用**：过度偏置会让模型把无关词"听成"热词 —— 必须与置信度 + 纠错留痕同时上，不能单独上
- **云端 prompt 会外发词表**：词表本身非敏感，但需在 `app_main.py:1321-1325` 的隐私说明里补一句
- **ASR 仍不参与判定**：所有改动只在"音频 → 文字 → 纠错"，绝不越过 `core/verify.py` 的引用对齐
