# 前端改版方案：从「单页堆叠」到「助手式四页」

> **已修订**：本文的“四页结构”已被 `docs/信息架构-v2-20261019.md` 的“五页结构（首页工作台 / 助手 / 法规 / 行动 / 我的）”取代；本文保留作过程记录。

> 分支：`feature/ui-shell-redesign`
> 日期：2026-10-19
> 参考：`xiaokun-learn`（Vue + Capacitor 移动端）、豆包 App 移动端
> 当前入口：`ui_chat.py` 的 `build_ui()`（`app_main.py:1472` 已转发到这里；`app_main.py:1262` 的旧 Tab 版仅作 legacy 保留）

## 一、结论

建议采用 **「对话优先 + 工具次级」的四页结构**，而不是继续在现有单页上做样式修补。

- 底部四个一级入口：**助手 / 法规库 / 检索 / 我的**
- 对话只放「短消息 + 结果卡片」，完整结果进入**独立结果页**
- 所有条目从「展开手风琴」改成「列表 → 详情抽屉/详情页」
- 每个工具（法规地图、待办、时间线、对比、汇总、上线准备）各自一页，从法规库列表点进去
- 设置、历史、语音、数据覆盖、隐私从聊天页底部移到「我的」

一句话概括：**把现在一条无限长的页面，拆成「聊天页 / 结果页 / 工具页 / 设置页」四种稳定版式。**

## 二、现状诊断（为什么会「别扭」）

### 1. 全部功能堆在同一个滚动列里

`ui_chat.py:454` 只有一个 `gr.Blocks` 页面，自上而下依次是：

| 区块 | 位置 |
|---|---|
| 开场动画 | `ui_chat.py:459` |
| 顶部栏 | `ui_chat.py:465` |
| 欢迎区 + 6 张示例卡 | `ui_chat.py:470-486` |
| 新手教程（手风琴） | `ui_chat.py:488` |
| Chatbot（隐藏，仅 200px） | `ui_chat.py:474` |
| 当前结果（`@gr.render`） | `ui_chat.py:502` |
| 调整查询条件（手风琴） | `ui_chat.py:625` |
| 历史结果（手风琴） | `ui_chat.py:642` |
| 输入框 | `ui_chat.py:648` |
| 更多功能（手风琴，7 项） | `ui_chat.py:656` |
| 语音输入（手风琴） | `ui_chat.py:665` |
| 资料覆盖/条款检索（手风琴） | `ui_chat.py:675` |
| 页脚 | `ui_chat.py:685` |

没有路由、没有一级导航，所有东西靠向下滚动发现。

### 2. Chatbot 不是主角，结果块才是

- Chatbot 初始 `visible=False`、固定 `height=200`（`ui_chat.py:474`），对话内容几乎没有展示空间。
- 真正的内容由 `@gr.render` 直接铺在聊天框下面，形成「聊天记录一小条 + 巨型结果块」的割裂结构。
- 用户感知不到「一问一答」，只感知到「页面又长了一截」。

### 3. 结果内部层层嵌套手风琴

- 每条 `_item_card` 是一个 `gr.Accordion`（`ui_chat.py:255`）
- 依据与原文又是一个嵌套 Accordion（`ui_chat.py:228`）
- 待办分组、后续 N 项、已隔离、资料边界、阶段、区域卡片全是 Accordion（`ui_chat.py:330-449`）
- 展开一个套一个，页面高度不可控 → 「点一下页面无限拉长」

### 4. 聊天页视觉弱

- 没有用户/助手气泡体系，没有头像、时间、复制/重答。
- 输入框下方还挂着教程、更多功能、语音、条款检索等，输入框并不「吸底」。
- 移动端虽然做了媒体查询，但整体仍是桌面表单思维。

### 3.2 豆包移动端

- **首页 = 问候语 + 功能入口卡片 + 底部输入框**，不把设置和历史塞进首页。
- **聊天是独立页面**：左上角历史/菜单，顶部当前会话标题，中间气泡，底部输入框 + 语音/附件/发送。
- **底部一级导航**（4–5 个，随版本变化）：首页/对话、发现、创作、通知、我的。
- 输入区始终吸底，语音入口显眼。
- 设置、历史、个人中心全部在「我的」或抽屉里。
- 视觉克制：大留白、少边框、少折叠，功能靠「卡片 → 二级页」而不是手风琴。

来源：
- [豆包使用教程](https://www.php.cn/faq/2041590.html)
- [豆包安卓 8.6.0 UI 大改（LINUX DO）](https://linux.do/t/topic/639645)
- [「豆包」AI 智能助手原型拆解](https://blog.csdn.net/lemonliyi/article/details/155524632)

### 3.3 两个参考的共同结论

1. **一级功能不超过 5 个，底部导航固定可见。**
2. **聊天页与结果/内容页分离**，聊天页永远只有消息和输入框。
3. **列表页只放摘要，详情进入下一层**；不在列表里无限展开。
4. **设置类内容不进主流程**，统一收进「我的」。

## 四、目标信息架构

### 4.1 四个一级页面

```
┌─────────────────────────────────────┐
│  合规雷达 · 出海助手        [历史] [+] │  顶部栏
├─────────────────────────────────────┤
│                                     │
│            页面内容区                │
│                                     │
├─────────────────────────────────────┤
│   💬 助手   📚 法规库   🔍 检索   👤 我的 │  底部导航（固定）
└─────────────────────────────────────┘
```

| Tab | 职责 | 包含 |
|---|---|---|
| **助手** | 对话与本次结果 | 欢迎/建议卡、消息气泡、结果摘要卡、结果页、输入框、语音 |
| **法规库** | 六个业务工具 | 工具列表页 → 单个工具页（地图/待办/时间线/对比/汇总/上线准备/六阶段路线） |
| **检索** | 条款检索 | 法规编号 + 标题关键词 + 正文结果 |
| **我的** | 设置与资料 | 历史结果、查询条件、语音设置、数据覆盖、隐私边界、版本信息 |

### 4.2 页面流转

```
助手（空态）
  ├─ 输入 / 点建议卡 → 助手（对话态）
  │       └─ 产生结果 → 结果摘要卡 → 结果页
  │                               └─ 点条目 → 右侧详情抽屉
  ├─ 顶栏「历史」→ 历史抽屉 → 打开旧结果 → 结果页
  └─ 顶栏「＋」→ 新对话

法规库（工具列表）
  └─ 点工具卡 → 工具页（筛选栏 + 结果列表）
                  └─ 点条目 → 详情抽屉

检索 → 输入编号 → 条款正文列表

我的 → 二级页/抽屉（历史、条件、语音、覆盖、隐私、关于）
```

## 六、Gradio 6.2 技术落地方案

### 6.1 页面壳：`gr.Tabs` + CSS 底部导航

```python
with gr.Blocks(...) as demo:
    with gr.Tabs(selected="assistant", elem_id="cr-tabs") as tabs:
        with gr.Tab("助手", id="assistant"):
            ...
        with gr.Tab("法规库", id="library"):
            ...
        with gr.Tab("检索", id="search"):
            ...
        with gr.Tab("我的", id="me"):
            ...
```

- `gr.Tab` 在 6.2 支持 `id`，`gr.Tabs` 支持 `selected`，可用 `gr.update(selected="library")` 做程序化跳转。
- 移动端把原生 tab 条用 CSS 固定到底部：`#cr-tabs > .tab-nav { position: fixed; bottom: 0; ... }`。
- 桌面端保持顶部/左侧横向导航，或同样底部但居中。
- 如果 6.2 的 tab DOM 结构导致 CSS 脆弱，备选方案：自定义一行 `gr.Button` 做底部导航，页面用 `gr.Column(visible=...)` 切换；逻辑更可控，代价是要自己维护选中态。

### 6.2 助手页：Chatbot 成为主角

```python
chat = gr.Chatbot(
    type="messages",
    layout="bubble",
    avatar_images=(None, "assets/avatar.png"),
    height=None,                 # 用 CSS 撑满视口
    elem_id="cr-chat",
    show_label=False,
    autoscroll=True,
    group_consecutive_messages=False,
)
```

- 把 `submit_message` 的返回值改为 `messages` 列表（`{"role": "user"/"assistant", "content": ...}`）。
- 助手消息只放**短摘要**：「已生成《…》，3 项优先 / 12 项待办」。
- 摘要下方用独立按钮「查看完整结果 →」切到结果页（`gr.Column(visible=...)` 切换）。
- 输入框、语音、快捷指令只属于助手页，不再出现在结果页/工具页。
- 流式/等待态：Gradio 的 `show_progress` 已可用；如需打字点，用 `gr.HTML` 状态条或 `Chatbot` 的空 assistant 消息 + CSS。

### 6.3 结果页：一个页面 + 一个详情抽屉

- 结果页是助手页内部的第二个 `gr.Column`（`chat_view` / `result_view`），用 `visible` 切换，顶部提供「← 返回对话」。
- `@gr.render(active)` 只渲染结果页，不再渲染到聊天列。
- 条目结构改为：
  - 第 1 层：紧凑行卡（类型标签、标题、一句话、状态 chip、`详情 →`）
  - 第 2 层：`gr.Sidebar(label="条目详情", position="right", open=False)` 抽屉
- 抽屉内容复用现有 `_item_card` 里的依据/来源/摘录代码，不再用嵌套 Accordion。
- 列表默认只展示 3–5 条，其余进入「全部条目」子视图（同一结果页内的列表视图，或分页），不再「查看后续 N 项」手风琴。
- 全页最多保留 **1 个** Accordion：资料边界与待确认事项。

### 6.4 法规库：列表 → 工具页

- 法规库页用 2 列卡片网格（移动端单列）。
- 点击卡片设置 `library_view` 状态，显示对应工具 `gr.Column`，其他隐藏。
- 每个工具页：
  - 顶部返回 + 标题
  - 吸顶筛选行（类目、市场、时间窗、市场多选）
  - 结果区复用现有 `run_map` / `run_todo` / … 的输出
- 初版可以继续用现有的 `render_m1/render_m3/...` HTML；第二阶段再把长 HTML 改成卡片列表。

### 6.5 我的：列表行 → 二级页/抽屉

- 一级页只放列表行，不直接放表单。
- 历史结果：`gr.Sidebar(position="left")` 或独立子页，复用现有 `history_options` / `open_history`。
- 查询条件：独立子页，复用 `update_conditions`。
- 语音：独立子页，复用 `transcribe` / `undo_voice`。
- 数据覆盖、条款检索、隐私：各自子页或抽屉。

### 6.6 CSS 重构

建议把 `assets/chat.css` 拆成三层：

1. **tokens**：颜色、圆角、阴影、字号、安全区（直接对齐 `xiaokun-learn` 的 `:root`）
2. **layout**：appbar、页面容器、底部导航、安全区

## 九、风险与注意事项

1. **Gradio DOM 选择器**：底部导航若依赖 `.tab-nav`，升级 Gradio 可能失效；建议同时在 `selftest_ui_contract.py` 加结构断言。
2. **状态复杂度**：四页 + 结果页 + 工具页会引入更多 `visible` 状态，建议统一成一个 `view` 状态机（`assistant` / `result` / `library` / `tool:map` / …），避免回调散落。
3. **现有浏览器回归全部依赖 `#cr-input`、`.cr-result-header`、`.cr-item > button` 等选择器**，改版必须同步更新，否则线上验收会假失败。
4. **移动端键盘遮挡**：使用 `100dvh` 与 `env(safe-area-inset-bottom)`，不要用 `100vh`。
5. **历史结果/导出仍绑定结果 ID**：结果页切换不能丢失 `active` 状态，`prepare_export` 的校验逻辑保持不动。
6. **旧 Tab 版 `build_legacy_ui`**：确认无脚本引用后可删除，避免后续误改。
