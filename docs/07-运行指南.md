# 怎么跑 —— ComplianceRadar 运行指南

> 这一堆 `.py` 分成三类：**能直接跑的**、**被调用的库**、**数据管线**。
> 别全都去跑，大部分是零件，不是入口。

.venv/Scripts/python.exe -m pip install -r requirements.txt

**本机已建好的环境**（推荐直接用这个）：

```
C:\Users\Kevin\.workbuddy\binaries\python\envs\default\Scripts\python.exe
```

下文用 `PY` 代表这个 python 路径，复制时替换即可。

## 三·五、想用语音输入？（可选）

语音只是「① 智能判定」页签的另一种输入方式，**不装也能跑**：装不上或没配好时，
麦克风控件自动变灰、页面提示「语音入口：未启用」，打字链路完全不受影响。

### 本地识别（默认，零密钥）

```bash
# ① 装可选依赖（含 faster-whisper + 兼容版 av，约 50MB）
PY -m pip install -r requirements-asr.txt

# ② 下模型（约 464MB，只需一次；默认走 hf-mirror 并关闭 Xet）
PY scripts/prepare_asr.py

# ③ 验证（离线可跑，23 项）
PY scripts/selftest_voice.py
```

模型落在 `C:\Users\<你>\.cache\compliance-radar\asr\faster-whisper-small`，
`core/asr.py` 会自动发现，无需配 `ASR_MODEL_DIR`。

### 云端识别（不下模型，零新增依赖）

```bash
# .env 或命令行环境变量
ASR_BACKEND=cloud
ASR_API_BASE=https://<你的服务>/v1
ASR_API_KEY=<key>
ASR_MODEL=<whisper-1 之类的模型名>
```

也可以用 `ASR_BACKEND=local|auto` 显式指定；`auto`（默认）按「有云端配置 → 云端，否则本地」选。

### 跑不通时按这三个坑排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `ProxyError 502` / 一直卡住 | HuggingFace 直连不通 | `prepare_asr.py` 已默认 `HF_ENDPOINT=https://hf-mirror.com`；手工下载时自己带上 |
| `401 CAS` / Xet 存储报错 | 新版 HF 走 Xet 存储 | 加 `HF_HUB_DISABLE_XET=1`（脚本已设） |
| 模型下完了但目录是空的 | Windows 建不了缓存软链接 | 用 `local_dir` 落实体文件（`prepare_asr.py` 就是这么做的） |
| `TypeError: ... metadata_errors` | `av>=19` 移除了该参数，faster-whisper 1.2.1 还在传 | `pip install "av<19"`（已锁进 `requirements-asr.txt`） |

### 部署时录音或上传入口不可用

录音与音频上传共用同一 ASR 后端；默认 `requirements.txt` 不安装可选的 `requirements-asr.txt`。没有完整云端配置、也没有本地识别依赖时，控件会禁用，页面会明确显示「录音/上传转写暂不可用」、原因及配置字段；重新上传音频不能解决这个配置问题。配置已识别的提示不代表后端连接或本地模型加载已经验证。

云端方式：在空间的私密环境变量中设置 `ASR_BACKEND=cloud`、`ASR_API_BASE`、`ASR_API_KEY`、`ASR_MODEL` 后重启，地址须兼容 `/audio/transcriptions`。不要把密钥写进代码或公开文件。网页对话模型的密钥不能视为已开通语音服务。新版应用先加载项目 `.env`，再读取 ASR 配置；修改配置后必须重启。

本地方式：需要安装可选依赖，并在启动前准备好与 `ASR_LOCAL_MODEL` 匹配的模型。若准备 `tiny`，必须显式设置 `ASR_LOCAL_MODEL=tiny`；默认仍为 `small`，不会自动选择另一个型号。本轮只在 Windows 的双逻辑 CPU 限制下验证 tiny 和公开短音频，Linux/Python 3.11 二进制依赖解析通过，但未验证魔搭容器内的下载、启动、60秒音频及并发延迟，因此未将本地 ASR 加入魔搭默认依赖。

### 这层如何控制错误边界

转写结果**只回填输入框**，不会自动查询法规。用户必须先检查、必要时修改文字，再点击「开始判定」进入 M1.5；最终判定使用输入框中的当前文字。

法规结论仍然 100% 来自核对语料 + `verify` 引用对齐，但转写错误**可能改变品类或市场**，因此不能把语音识别结果直接当作合规结论。转写失败时只提示原因，不覆盖原有输入，也不显示法规结论。

## 四、数据管线（只有要更新法规语料时才跑）

**顺序不能乱**，前者是后者输入：

```bash
PY scripts/fetch_eu.py       # 1. 抓欧盟（EUR-Lex SPARQL）需联网
PY scripts/fetch_us.py       # 2. 抓美国（eCFR API）需联网
PY scripts/merge_corpus.py   # 3. 合并 + 去重 + 体检
PY scripts/check_links.py    # 4. 逐条实测链接
PY scripts/enrich_cn.py      # 5. 补中文名（需 .env Token）
PY scripts/make_overview.py  # 6. 生成数据总览
PY scripts/make_todo_eu.py   # 7. 生成欧盟待补清单
```

**一键跑全流程**：

```bash
run_pipeline.bat      # 双击，或命令行执行
```

> ⚠️ `check_links.py` 默认**非破坏写入**（只补空值，保留已有人工结论）。
> 要强制覆盖加 `--force`。

**管线产出**（跑完会刷新）：

```
data/eu_regulations.csv          欧盟原始抓取
data/us_regulations.csv          美国原始抓取
data/语料核对表_骨架总表.csv      合并结果
data/语料核对表_完整版.csv        ⭐ M1 读的是这个
data/数据总览.md / 骨架体检报告.txt / 链接检查报告.txt
```

## SQLite 条款库与正文候选更新

配置 `COMPLIANCE_DB_PATH` 为已有库的绝对路径；默认探测项目内或项目同级的 `sqlite/regulations.sqlite3`。必需表为 `laws/documents/law_documents/units`。库未配置时首页显示状态，条款页给出缺库提示，原 CSV 功能继续可用。正式库不随源码上传。

在“条款检索”页输入完整 CELEX 或 `16 CFR Part 1250`，标题关键词可留空；多个关键词同时匹配 heading。默认最多 12 片、24000 字符，截断会显示提示。抽取正文未经适用性审核，不自动生成执行任务。

```bash
# 第一步：只抓取候选，不写库；每次 --law 指定一条法规
python scripts/sync_law_content.py --law US:16:1250 --db /path/to/regulations.sqlite3
python scripts/sync_law_content.py --law 32009L0048 --db /path/to/regulations.sqlite3
# 或读取元数据核验生成的 changes 信号
python scripts/sync_law_content.py --signals sqlite/metadata_check_latest.json --db /path/to/regulations.sqlite3
```

候选默认位于 `data/content_staging`，包含 `body/diff/raw_hex/raw_sha256/sha256/base_sha256/source_url`。人工核查原文、版本和差异后，将输出中的 candidate 与 sha256 分别作为下列参数；在 Bash 中先赋值再执行：

```bash
read -r -p '已审阅候选 JSON 路径: ' CANDIDATE
read -r -p '确认正文 SHA256: ' BODY_SHA256
python scripts/sync_law_content.py --apply "$CANDIDATE" --confirm-sha256 "$BODY_SHA256" --db /path/to/regulations.sqlite3
python scripts/selftest_law_store.py
python scripts/selftest_all.py
```

入库前自动生成同目录 `regulations.sqlite3.bak-UTC时间戳`，开启 `BEGIN IMMEDIATE`，同步 documents、units 和存在的 documents_fts；核验原始响应哈希、正文哈希、来源标识、旧正文哈希及数据库一致性。已变化的候选必须重新抓取审阅。重复应用返回 unchanged；新建记录保留待核对。恢复时先停止所有使用该库的服务，再将返回的 backup 文件复制回原路径；例如使用 `python -c "import shutil; shutil.copy2('regulations.sqlite3.bak-实际时间戳', 'regulations.sqlite3')"`，路径替换为此次返回的真实值。

eCFR 的快照日期、修订编入日期与 FR 法律生效日分别保存，不相互替代。官方接口出现 406、WAF 页面、空正文或不支持的结构时会留存 failure.json，不覆盖旧正文。EUR-Lex 部分勘误英文正文是否可用须逐条核实，本轮没有正式库，未核验历史 155/173 统计。

## 六、常见问题

**Q：报 `ModuleNotFoundError: No module named 'openai'`**
依赖没装。跑 `.venv/Scripts/python.exe -m pip install -r requirements.txt`。

**Q：界面里法规清单有，但没有「卖家提示」**
正常——没配 `.env` 的 Token，走的是降级路径。数据完整、链接可核验，只是少了模型润色。

**Q：欧盟链接点不开**
正常。EUR-Lex 有 AWS WAF 人机验证墙，**用浏览器打开是好的**。
程序访问返回 202 不代表链接失效 —— 详见 README「关于『链接打不开』的判定规则」。

**Q：改了代码，怎么确认没破坏红线**
跑 `PY scripts/selftest_m1.py`，26 项全绿就说明引用对齐和防幻觉还好的。

**Q：`audit_guide.py` 直接跑报错**
它**必须传一个指南文件路径**（没有 `--help`）。无参数直接跑只会打印用法：

```bash
PY scripts/audit_guide.py docs/04-官方来源判定指南.md
# 或设环境变量
GUIDE_PATH=docs/04-官方来源判定指南.md PY scripts/audit_guide.py
```

**Q：`check_links.py` 会覆盖我填的核对结果吗**
不会。默认**非破坏写入**，只补空值，已有结论保留。要覆盖得显式加 `--force`。
