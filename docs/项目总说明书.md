## 一、项目定位

ComplianceRadar 是面向跨境电商卖家、外贸工厂、国内电商转出海团队和天猫 OPC 孵化团队的出海合规自查工作台。

用户输入“卖什么、卖到哪里”，系统从本地维护的结构化法规语料中查询适用法规，展示法规变化、待办动作、区域差异和 OPC 上线准备事项。每条法规结果尽量保留官方编号和官方链接，便于用户回到原文复核。

项目当前定位是：

- 结构化法规查询工具；
- 法规变化和执行事项整理工具；
- 多区域合规差异对比工具；
- OPC 上线前的准备事项工作台。

项目当前不承担正式法律意见、产品认证、商品自动判定合规、律师审查或政府审批。

## 三、功能清单

### M1 合规地图

按“品类 + 市场”从本地 CSV 语料表中筛选法规。

输出内容包括：

- 法规中文名；
- 官方英文标题；
- 官方编号；
- 欧盟法规的 CELEX / ELI 信息（美国可为空）；
- 官方链接；
- 来源类型；
- 生效日期或待核实状态；
- 现行效力；
- 人工核对状态。

M1 使用确定性筛选，不让模型凭记忆新增法规。

### M1.5 智能判定

用户可以用一句话描述业务，例如“我要把洋娃娃卖到美国去”。系统尝试识别：

- 商品品类；
- 目标市场；
- 用户是否明确说出了不支持的品类或市场；
- 识别依据和槽位来源。

识别成功后复用 M1 的确定性查询结果。模型只负责理解输入，法规结果仍来自本地语料和规则。

当前边界：

- 品类和市场是单值槽位；
- 输入给模型的业务文本和上下文各最多取前 500 个字符；
- 超时后使用本地词典兜底；
- 不支持多品类 × 多市场矩阵路由；
- 不能计算“相对另一个市场新增了哪些义务”；
- 没有文件上传和文件解析功能。

### M2 变化时间线

按法规事件整理变化时间线，支持：

- 公布；
- 生效；
- 开始适用；
- 修订；
- 废止；
- 过渡截止；
- 首次收录参考事件。

首次收录参考事件不等同于法律生效事件。远期未来事件不会被默认截断。

### M3 合规待办

把已通过人工核对门禁的法规转换为卖家可以执行的动作，例如：

- 标签标识；
- 检测测试；
- 注册备案；
- 认证文件；
- 记录留存；
- 切换替换；
- 限制禁售；
- 合规确认。

每条待办包含：

- 动作；
- 动作类型；
- 适用条件；
- 执行期限；
- 紧迫度；
- 法规编号；
- 官方链接；
- 证据说明；
- 稳定 `action_id`。

美国 57 条待核对法规不会进入可执行待办，也不会进入 M7 的执行清单。

M3 支持 CSV 导出，空清单不能导出。

### M4 模型对照

M4 用于展示通用模型和本项目规则结果的差异。

当前状态是占位：

- 固定题干为儿童玩具 × 欧盟；
- 没有真实完整的历史模型回放；
- 页面显示尚未生成对照记录时，不能把占位内容当成真实对照实验。

### M5 区域对比

对同一品类比较欧盟和美国的法规：

- 共同法规只按官方编号完全匹配；
- 区域独有法规分别展示；
- 不按名称相似度推断两个法规具有同等法律效力；
- 对待核对区域保留状态提示。

### M6 多区域汇总

一次选择多个市场，对同一品类的法规进行按区域汇总：

- 每个区域独立统计；
- 展示通过、待核对和被拦截数量；
- 明确处理区域查询失败和部分成功；
- 用户明确取消全部市场时拒绝查询。

### M7 OPC 上线准备

将已核对法规对应的 M3 动作整理为 OPC 上线阶段任务：

1. 选品与范围；
2. 打样与测试；
3. 标签与上架；
4. 文件与认证；
5. 供应链留档；
6. 切换与复核。

每项任务可展示：

- 责任角色；
- 优先级；
- 状态；
- 适用条件；
- 紧迫度；
- 法规依据；
- 官方链接。

M7 支持导出 OPC 执行清单 CSV。它是上线准备事项编排，不是“商品已经合规”的判定。

### 4.3 AI 与规则的分工

模型主要负责：

- 识别自然语言中的品类和市场；
- 摘要和表达润色；
- 将结构化结果组织成用户易懂的文字。

确定性代码负责：

- 法规筛选；
- 法规编号和唯一键；
- 日期事件；
- 官方链接白名单；
- 引用对齐；
- 人工核对门禁；
- M3/M7 是否允许生成可执行任务；
- 区域对比和 CSV 导出。

模型失败、超时或格式错误时，系统回退到本地规则路径，尽量保留确定性结果。

### 4.4 语音输入与 ASR 边界

语音输入是 M1.5 的输入端，不建立第二条法规判定链路：

- `core/asr.py` 只负责音频转文字，不负责商品分类、市场识别或法规查询；
- 转写按钮只把文字回填到 M1.5 输入框，不自动调用判定；用户核对或修改后，点击「开始判定」才进入现有 `m15_router` 和法规核验链路；
- 转写错误可能改变品类或市场，界面和运行指南均要求人工核对；转写失败不覆盖原输入，也不显示法规结论；
- 支持可选的本地 `faster-whisper` 和云端 OpenAI-compatible `/audio/transcriptions` 后端；两者均不可用时，文字输入仍可用，语音入口置灰；
- 音频限制为 RIFF/WAVE、最大 10 MiB、最长 60 秒；单次等待上限 45 秒，最多 2 个并发任务；
- 转写缓存默认关闭，云端后端会将录音发送到配置的服务，不应输入客户敏感信息；
- 相关配置位于 `.env.example`，可选依赖位于 `requirements-asr.txt`。

### 4.5 DeepSeek 配置

当前配置方式保持不变，代码从环境变量读取：

```python

BASE = os.getenv("MODEL_API_BASE", "").strip().rstrip("/")
MODEL = os.getenv("MODEL_NAME", "").strip()
```

`.env`、Token 和个人配置不能上传 GitHub 或 ModelScope。在线平台通过环境变量或 Secret 注入。

## 五、性能、缓存和超长输入边界

### 5.1 M1.5 智能判定

- 模型硬超时：12 秒；
- 进程内解析缓存最多 128 项；
- 缓存键是 SHA-256，不保存原文；
- 模型失败后使用本地词典；
- 同一输入重复查询可快速返回。

### 5.2 通用模型调用

现状（2026-10-18 起）：

- OpenAI 兼容客户端 socket timeout 为 120 秒，SDK 自带重试关闭（`core/llm.py:121`）；
- 整体超时预算默认 45 秒，可用 `LLM_TIMEOUT_SECONDS` 覆盖；预算会下传到底层 HTTP，让底层先收口；
- M1/M2/M3 润色未显式传值时自动套用该预算，不再无限等待；
- 在途调用上限（默认 4，可用 `LLM_MAX_INFLIGHT` 覆盖），池满直接返回降级结果，不无界排队；
- 磁盘缓存 `data/cache/` 已有治理：
  - 缓存键包含提示词、Base、Model、生成参数、思考开关与格式版本（`core/llm.py:126`），**不含 Token**；
  - TTL 默认 7 天（`LLM_CACHE_TTL_SECONDS`）、条目上限 512（`LLM_CACHE_MAX_FILES`）、单条 200KB（`LLM_CACHE_MAX_BYTES`）；
  - 原子写入，目录不可建或文件损坏均按「未命中」处理，不阻断主链路。

**限制并未消失**：超时后 Python 无法强杀底层 HTTP 线程，该次请求会在后台跑完才释放连接；
因此「连续慢请求」只能被限制在预算内降级，不能立即回收线程。

### 5.3 超长上下文

当前版本不是长文档分析系统：

- 没有文件上传；
- 没有 PDF、Word、Excel 解析；
- 没有分块、向量检索或全文索引；
- M1.5 模型输入只使用前 500 个字符的业务输入和前 500 个字符的上下文。

因此，“把整份合同、BOM 或产品文件交给系统自动分析”属于后续版本能力，不能写成当前已支持功能。
